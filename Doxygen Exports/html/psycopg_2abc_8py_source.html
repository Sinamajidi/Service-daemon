127 def get_key(self, obj: Any, format: PyFormat) -> DumperKey:
128 """Return an alternative key to upgrade the dumper to represent `!obj`.
129
130 :param obj: The object to convert
131 :param format: The format to convert to
132
133 Normally the type of the object is all it takes to define how to dump
134 the object to the database. For instance, a Python `~datetime.date` can
135 be simply converted into a PostgreSQL :sql:`date`.
136
137 In a few cases, just the type is not enough. For example:
138
139 - A Python `~datetime.datetime` could be represented as a
140 :sql:`timestamptz` or a :sql:`timestamp`, according to whether it
141 specifies a `!tzinfo` or not.
142
143 - A Python int could be stored as several Postgres types: int2, int4,
144 int8, numeric. If a type too small is used, it may result in an
145 overflow. If a type too large is used, PostgreSQL may not want to
146 cast it to a smaller type.
147
148 - Python lists should be dumped according to the type they contain to
149 convert them to e.g. array of strings, array of ints (and which
150 size of int?...)
151
152 In these cases, a dumper can implement `!get_key()` and return a new
153 class, or sequence of classes, that can be used to identify the same
154 dumper again. If the mechanism is not needed, the method should return
155 the same `!cls` object passed in the constructor.
156
157 If a dumper implements `get_key()` it should also implement
158 `upgrade()`.
159
160 """
161 ...

164 """Return a new dumper to manage `!obj`.
165
166 :param obj: The object to convert
167 :param format: The format to convert to
168
169 Once `Transformer.get_dumper()` has been notified by `get_key()` that
